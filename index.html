01 / THE PHILOSOPHYSTART WITH THE QUESTION

What if software
didn't have to start over?

Software evolves. Requirements change. Entirely new ideas emerge. Yet too often, the architecture decides in advance what an application can become.

AxetosOS starts from a different assumption: capabilities shouldn't be permanently trapped inside the products they were originally built for.

01 —

Everything can be a capability.

UI elements, services, tools, logic and entire product features can be built as independent modules.

02 —

Composition beats confinement.

Reuse what exists. Connect independent capabilities. Create products without a prescribed stack or industry.

03 —

Change without rebuilding everything.

Extend, customize and eventually replace capabilities while preserving the parts that already work.

04 / SEAMLESS EVOLUTIONDESIGN TARGET

Upgrade the system.
Not the interruption.

Imagine replacing an active Display Module while an object is rotating. The new version loads and validates alongside the old. When ready, it takes over at a safe boundary — without resetting the object or interrupting the user.

01

Keep the working version active

02

Load and test the new candidate

03

Handover when ready; otherwise keep the old one

True seamless handover depends on compatible contracts, state management and resources. It is a design goal, not a guarantee for every module.

05 / HOW THE IDEA GREWONE QUESTION LEADS TO ANOTHER

It started with
one limitation.

AxetosOS didn't begin as an attempt to reinvent software. It began with a practical desire to let people change the way their CRM looked and worked.

01 / THE START

Let customers customize their CRM.

Give users more control over the software they depend on.

02 / THE QUESTION

Why can't the tools be customizable too?

If controls and editors are made from Modules, the development environment itself can evolve.

03 / THE VISION

Why stop at applications?

With the right Modules, the platform should be able to develop virtually anything — including software categories that have not yet been imagined.

06 / WHERE IT STANDSVISION & IMPLEMENTATION

Ambitious by design.
Grounded in actual work.

AxetosOS is an independent R&D project. Its architecture has evolved through working experiments and substantial refactoring. The long-term vision is larger than the features available today.

CURRENT FOUNDATION

Native desktop direction

A .NET / Avalonia desktop foundation, small startup architecture and early Module-driven environment form the current development direction.

ACTIVE ARCHITECTURAL WORK

Modular discovery & composition

Developing clearer Module contracts, recursive composition and independent capabilities rather than prescribed numbered layers.

LONG-TERM VISION

Live replacement & product extension

Validated module handover, self-hosted tooling and post-compilation customization of AxetosOS-authored products remain design targets.

RELATED ENGINEERING WORK

Ideas explored through real systems.

Past and parallel projects include CRM tooling, an NES emulator and a market-data server — practical work that informs the platform's direction.
